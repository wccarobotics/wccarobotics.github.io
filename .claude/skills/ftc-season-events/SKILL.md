# FTC Season Events

This skill keeps the season-wide events page up to date: [tournaments/ftc/biobuzz/index.md](../../../tournaments/ftc/biobuzz/index.md)
lists every event of the season with posted match results, with its average and top OPR and high
score as a rough measure of the level of competition, linking each one's livestream or video
and a stats page generated by `tools/ftc-stats/FtcStats.cs` (qualification stats, then the playoffs
and awards when the event has them; the table's Winners column comes from the playoffs).

The deterministic parts are scripted. This skill covers the judgment around them: finding and
confirming videos, and checking the generated pages for problems.

For a full results page for one event (every match with a timestamped video link, playoffs and
awards), use the **ftc-tournament-analyzer** skill instead. Offer it for events WCCA's team attended.

## Files

| File | What it is |
|---|---|
| `tools/ftc-stats/build_season_pages.py` | Regenerates the index and every event's stats page from the FTC Events API |
| `tools/ftc-stats/FtcStats.cs` | .NET 10 stats tool the build script runs for each event |
| `tools/ftc-stats/season-videos.json` | Videos found by searching, by event code (the API's own livestream links are added automatically) |
| `.claude/skills/ftc-season-events/find_videos.py` | Lists candidate videos for events that don't have one yet |
| `.claude/skills/ftc-season-events/channels.json` | YouTube channels that stream FTC events, checked by `find_videos.py` |

## Prerequisites

- `ftc-api-credentials.json` at the repo root (see the FTC Events section of `.github/copilot-instructions.md`).
- .NET 10 SDK (`dotnet --list-sdks`), Python 3, and Node.js (yt-dlp uses it for YouTube's JS challenges).
- yt-dlp installed with pip: `python -m pip install --user --upgrade yt-dlp`.

**Always run yt-dlp as `python -m yt_dlp`**, never plain `yt-dlp`. On the dev PC, Windows App Control
blocks the standalone `yt-dlp.exe`. Also pass `--js-runtimes node --remote-components ejs:github` on
every call: without it some videos fail with "This video is not available" even though they play
fine. `find_videos.py` does both.

## Workflow

### 1. Regenerate the pages

```bash
python tools/ftc-stats/build_season_pages.py
```

It prints one line per event (qual matches, teams, videos). Compare with `git status` /
`git diff --stat tournaments/ftc/biobuzz/` to see which events are new or changed.

### 2. Find videos for events without one

```bash
python .claude/skills/ftc-season-events/find_videos.py --days 21
```

Use `--days` to cover everything since the last refresh (`--days 60` for a full pass). It takes a
minute or two. For each event without a video it prints the event's website, **channel matches**
(recent streams and uploads on the channels in `channels.json` dated near the event and sharing a
word with its name or city) and **search** results. At the end it lists recent FTC-looking videos
on those channels that matched no event.

Also check, by hand:

- **The event's website** (printed by the script). Regional sites sometimes link the stream.
- **Abbreviated names.** Streams often use a league's short name ("NEFL Meet 1" for Northeast
  Florida Meet 1, "MSCRL", "SoCal League C2"), which shares no word with the event name, so the
  script misses them. Search for the abbreviation, and check the channels that streamed the
  league's earlier events.
- **The "didn't match" list.** Streams with generic titles ("Saturday Stream", "FIRST Tech
  Challenge - October 3") land here; match them to events by channel region and date.
- **YouTube searches sorted by upload date**, by region and event type ("FTC league meet",
  "FTC scrimmage", "FTC Oklahoma", "FTC Georgia", …). On a busy weekend this found more than the
  per-event searches did:
  `python -m yt_dlp --no-warnings --js-runtimes node --remote-components ejs:github --flat-playlist --playlist-end 12 --print "%(id)s | %(channel)s | %(title)s" "https://www.youtube.com/results?search_query=FTC+league+meet&sp=CAI%3D"`.
  (`sp=CAI%3D` is YouTube's "sort by upload date". yt-dlp's `ytsearchdate` prefix is no longer
  supported, and plain `ytsearch` ranks by relevance, so it fills up with past seasons' videos.)
  Results still mix in old seasons and unrelated "FTC" (Federal Trade Commission) news, so filter by
  title and date. Streams that are still live have no duration yet.
- **Ambiguous videos:** for a stream whose title and description don't name the event (Okarche
  Warriors' "FTC Robotics League Meet", Oct 24, when Oklahoma had four meets), grab frames and read
  the screen. See "Identifying a stream from its frames" below.

#### Identifying a stream from its frames

Most event streams show the FTC scoring system's overlay: the event name and city, the match
("Qualification 3 of 21"), and the four teams with names. Grab a handful of frames without
downloading the video (put them in their own folder under `.scratch/`):

```bash
mkdir -p .scratch/frames-VIDEO_ID && cd .scratch/frames-VIDEO_ID
URL=$(python -m yt_dlp --no-warnings --js-runtimes node --remote-components ejs:github -g -f 311/232/300/95/136 "https://www.youtube.com/watch?v=VIDEO_ID" | head -1)
for t in 1200 2400 3600 5400 7200; do ffmpeg -hide_banner -loglevel error -ss $t -i "$URL" -frames:v 1 -y f$t.png; done
```

(Formats 311 and 95 are 720p HLS; some videos only have DASH formats, where 136 is 720p. Check `-F` if none are available. Pick times within the video's duration.)
Read the frames, then confirm against the API: the overlay's event name should match the event,
and a match shown on screen should have the same four teams on the same alliances as that match in
`schedule/{event}?tournamentLevel=qual` (also check the qualification count, e.g. "of 21").
Pre-match screens such as the robot-inspection board list every team at the event, which also works.
If the frames show nothing identifying, leave the video out rather than guess.

Save frames as PNG: some streams' color range makes ffmpeg's JPEG encoder fail ("Non full-range YUV"),
which looks like a failed read but isn't.

A stream that ended only a few hours ago may not be ready: YouTube offers only DASH formats from
the live broadcast (no HLS, no storyboards), ffmpeg can't seek into them, and `--download-sections`
clips come out undecodable. Check again later, or rely on other evidence: e.g. a sibling stream
on the organizer's own channel with the same title pattern ("FTC - 23/10" confirmed from frames,
so "FTC - 24/10" is day 2).

**Don't open videos in the built-in browser** to look at them: they autoplay, and the user hears
the audio even when the browser panel is hidden.

### 3. Confirm each candidate before adding it

Get the details:

```bash
python -m yt_dlp --no-warnings --skip-download --js-runtimes node --remote-components ejs:github --print "%(title)s | %(channel)s | %(upload_date)s | %(duration_string)s | %(was_live)s | %(description).300s" "https://www.youtube.com/watch?v=VIDEO_ID"
```

Keep it only if all of these hold:

- **Right event:** the title or description names the event, venue or city, or links its
  ftc-events page. A shared word alone isn't enough: the script once matched Kazakhstan's
  "AI & Digital Bridge Cup" to New Hampshire's "Governor's Cup".
- **Right date:** the upload/stream date is the event day (streams can be dated the next day in UTC).
- **Right program and season:** FTC, not FRC (FRC's 2026 game is REBUILT; FTC's is BIOBUZZ) or FLL,
  and not a past season's event with the same name.
- **A real stream:** check the duration. Full event streams run hours; a stream of a few seconds
  or minutes is a false start (Bolles Live has a 16-second one for Oct 3). Skip robot reveals,
  game analysis and "Weekly Rundown" videos.
- **An official event:** unofficial events such as FUN's "Robot in 30 Hours" aren't in the FTC
  Events API and don't belong on the page.

### 4. Record the videos

Add confirmed videos to `tools/ftc-stats/season-videos.json`, in the order they should appear:

```json
"USMISAS": [
  { "label": "Day 1 livestream", "url": "https://www.youtube.com/live/PxsqeKP_bp8" },
  { "label": "Day 2 livestream", "url": "https://www.youtube.com/live/lr6iMORuxMs" }
]
```

- Labels: `Livestream` for one stream, `Day 1 livestream` / `Day 2 livestream` / `Field 1 livestream`
  for several, `Video` for an uploaded recording, `Match videos` for a playlist of per-match uploads.
- URLs: `https://www.youtube.com/live/VIDEO_ID` for livestreams, `https://www.youtube.com/watch?v=VIDEO_ID`
  for uploads (the site's convention).
- An entry with the same video ID as the API's `liveStreamUrl` replaces it (useful to relabel it).
- **Check the API's links too.** `liveStreamUrl` is sometimes a channel page rather than a video
  (`youtube.com/@team/live`, `twitch.tv/team`); those show nothing once the stream ends. Twitch
  usually keeps no recording: check `python -m yt_dlp --flat-playlist "https://www.twitch.tv/CHANNEL/videos?filter=archives&sort=time"`.
  Look for a recording on the team's YouTube channel (Stars of the Galaxy re-posts its streams
  there a day or so later), and if there's none, hide the API link:
  `{ "url": "https://www.twitch.tv/CHANNEL", "hide": true, "why": "no saved broadcast (checked DATE)" }`.

If a confirmed video came from a channel that isn't in `channels.json`, add the channel (handle from
`--print "%(uploader_id)s"`) so the next run checks it automatically.

Then run `build_season_pages.py` again so the pages pick up the videos.

### 5. Check the generated pages

The stats pages explain expected differences in plain notes. Know which are fine:

| Note on a stats page | Meaning |
|---|---|
| `Computed rankings match the official rankings.` | Normal. |
| `These rankings cover this meet only; the official rankings are league rankings…` | League meet; expected. |
| `The official rankings also count the N matches without posted scores…` | Some scheduled matches never got scores (they show as 0-0 in the API). Expected after an event ends. |
| `N scheduled qualification matches have no posted results and are left out.` | Finished event with unplayed or unposted matches. Expected. |
| `Def: … consistent with random variation … treat them as noise` / `not enough matches` / `can't be told apart from offense` | Normal; defense ratings are usually noise at small events. |
| `Warning: computed rankings differ from the official rankings for …` | **Investigate.** On a finished, non-league event this means the RP or tiebreaker rules in `FtcStats.cs` don't match the official ones (that's how the disqualification rules were found). On an in-progress event it can just mean the rankings and match results were fetched a moment apart; rerun. |
| `Warning: score details missing …` | The detailed scores lag the results; bonus RPs are undercounted. Rerun later. |

Events with only practice matches are listed as "Practice only" with no stats page. That's expected.

Build and look at the result:

```bash
bundle exec jekyll build
```

Start the `jekyll` preview server (`.claude/launch.json`) and check `/tournaments/ftc/biobuzz/`:
every Stats link loads, video links open the right video, and clicking a team number highlights it.

### 6. Report and commit

Tell the user which events are new, which videos were added (and how each was confirmed), and
anything that needs a look (warnings, events still without video). Commit and push only when the
user asks.

## API notes

- In `matches`, `score{Color}Foul` is the foul points that alliance **committed**, which are awarded
  to the opponent. Pre-foul score = own final score − opponent's foul value.
- `matches/{event}` without a level filter includes `PRACTICE` matches; ranked stats use `QUALIFICATION` only.
- `postResultTime` isn't a reliable "played" flag. Played matches can have real scores and an
  `actualStartTime` but no `postResultTime` (the official rankings count them), while abandoned
  matches show up as 0-0 with a start time and no `postResultTime`. The rule used everywhere
  (`Results.IsPlayed` in `FtcStats.cs`): posted, or started with a nonzero score.
- The `events` list's `liveStreamUrl` is sometimes set, and `webcasts` is usually null. `website` is
  often a regional calendar page rather than the event itself.
- 2026 ranking: average RP (3 per win, 1 per tie, +1 per bonus RP from the `...RP` flags in
  `scores/{event}/qual`), then average pre-foul score. A disqualified team gets 0 RP and 0 tiebreak
  points for that match, but its W-L-T still counts the match result.

## Browser fallback

If yt-dlp stops working, YouTube search works in the built-in browser: open youtube.com, then from
that tab `fetch('/results?search_query=...')` and parse the `var ytInitialData = {...};` JSON
(`videoRenderer` objects). Don't use `javascript_tool` inside `browser_batch` right after a
`navigate`; it runs before the page loads and returns nothing.
